# 组长教学与发布指南

## 上课前

1. 将仓库推送到你的 GitHub、Gitee 或组内 Git 服务，发实际克隆地址给组员。
2. 请组员提前准备 Python 和 C++ 编译器，按照 README 启动成功。
3. 执行 `python lab.py --test`、`python tests/verify_lessons.py` 和 `python tests/test_live.py`，确认基准与对照实验正常。
4. 课堂投屏时可放大浏览器；每位同学在本机修改代码并启动本地服务。

## 75 分钟教学安排

| 时间 | 内容 | 建议提问 |
| --- | --- | --- |
| 0–10 分钟 | 看默认动画，解释目标、反馈、误差、控制输出 | 电机怎么知道到位了？ |
| 10–25 分钟 | 只开 P，修改三个 Kp 值 | 更大的 Kp 一定更好吗？ |
| 25–35 分钟 | 加持续负载，计算 -load/Kp | 保持不动为什么还需要力矩？ |
| 35–45 分钟 | 加 I | 误差接近零时是谁在提供补偿？ |
| 45–55 分钟 | 加 D | 为什么开始减速时误差还没到零？ |
| 55–65 分钟 | 低力矩限幅、反向与抗积分饱和 | 电机输出不再增大，内部状态还会变化吗？ |
| 65–75 分钟 | 小组讨论与记录 | 如何用数据支持自己的参数选择？ |

不建议开场就让同学随机同时修改三个参数。先提出预测，再修改一个因素，用同一实验条件验证。

## 发布为可克隆的远程仓库

本项目不包含远程账号或访问凭据。先在你的 Git 服务创建一个空仓库，不勾选自动生成 README，再在本目录执行下列步骤。命令中的尖括号内容须替换为实际值。

如果当前目录还没有 Git 仓库，执行一次：

```bash
git init -b main
```

提交代码（如果已有初始提交且工作区干净，可跳过）：

```bash
git add .
git commit -m "Add C++ PID gimbal teaching lab"
```

配置远程并推送：

```bash
git remote add origin <你的远程仓库URL>
git push -u origin main
```

如果提示身份未配置，按你的真实 Git 身份设置 `user.name` 和 `user.email`。如果已存在 origin，先用 `git remote -v` 检查，不要重复添加。`build/` 已被忽略，不需要上传 exe 或本机生成的数据。

组员获取项目：

```bash
git clone <你的远程仓库URL> pid-gimbal-lab
cd pid-gimbal-lab
git switch -c experiment/your-name
python lab.py
```

组员完成后提交 `src/tuning.cpp` 和填写好的记录文件；用分支或 Fork 提交均可。原始 CSV 如需纳入提交，可复制到自己新建的 `results/姓名/` 目录，不要提交 `build/` 整个目录。

## 验证范围

- `python lab.py --test`：限幅、无效周期、测量微分、抗饱和、重置，以及默认负载下的收敛指标。
- `python tests/verify_lessons.py`：P/PI/PID 和抗饱和课程参数的真实 C++ 仿真对照。
- `python tests/test_live.py`：真实 C++ 常驻进程的指令、状态连续性、暂停、重置、热重编译和 HTTP 接口。
- CMake / CTest：独立编译 C++ 模块并执行控制器测试。
- `.github/workflows/check.yml`：推送至 GitHub 后在 Linux 上执行以上 Python 驱动测试与 JavaScript 语法检查。

发布前手工检查：打开页面，拖动 Yaw / Pitch 滑块，确认云台连续跟随；改变外力矩；暂停后确认时间冻结；目标归零后观察闭环返回；重置后确认角度和时间归零；切换曲线转轴并下载 CSV；最后修改 C++ 参数、重新编译，确认响应变化。浏览器检查和算法测试互为补充。
