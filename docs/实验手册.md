# PID 云台调参实验手册

## 1. 这次要学会什么

完成实验后，你应该能够解释闭环反馈、区分 P/I/D 的作用，在 C++ 中修改参数并用曲线说明结果，而不是仅凭“看起来更稳”判断。预计 60–90 分钟。

## 2. 从云台理解闭环

云台有两个转轴：Yaw 表示水平转向，Pitch 表示俯仰。我们希望它转到指定角度并保持住，即使受到外部力矩。

```text
目标角度 r ──→ [误差 e = r - y] ──→ [PID] ──→ [电机力矩限幅] ──→ [云台]
                    ↑ 负反馈                                      │
                    └──────────────── 测量角度 y ←─────────────────┘
```

单纯给电机一个固定力矩属于开环：它不知道云台是否已到目标。闭环则不断测量角度，用误差修正下一次输出。本仓库每 **2 ms** 计算一次控制输出，即 **500 Hz**。

本实验的输出是力矩，不是角度，也不是直接给电机的 PWM 占空比。

## 3. 三项分别在做什么

理想连续形式为：

```text
e(t) = r(t) - y(t)
u(t) = Kp · e(t) + Ki · ∫e(t)dt + Kd · de(t)/dt
```

实现位于 `include/pid.hpp`。本仓库为避免目标突变时产生微分冲击，实际 D 项使用**测量值的负微分**，并经过低通滤波：

```text
e[k] = target[k] - measurement[k]
candidate_integral = integral + e[k] · dt
raw_derivative = -(measurement[k] - measurement[k-1]) / dt
alpha = dt / (tau + dt)
derivative += alpha · (raw_derivative - derivative)
P = Kp · e[k]
I = Ki · integral
D = Kd · derivative
u = clamp(P + I + D, -max_output, +max_output)
```

积分是否接纳候选值取决于抗饱和逻辑；见实验五。首次采样的微分设为 0，避免未初始化历史值造成冲击。

| 项 | 直觉 | 本实验中的典型作用 | 调得过大时可能出现什么 |
| --- | --- | --- | --- |
| P | 偏得越多，用力越大 | 更快接近目标 | 超调、振荡、力矩饱和 |
| I | 长期有误差，就逐渐补力 | 补偿持续负载，减小稳态误差 | 超调加重、积分饱和、恢复慢 |
| D | 根据运动趋势提前减速 | 增加阻尼、减轻超调 | 对测量噪声敏感、输出抖动 |

这些是给定模型下的趋势，不是任何系统都适用的调参保证。D 项在匀速运动时可能非零，静止时趋近零。

内部角度统一为 **rad**，界面显示 **°**。`Kp` 的单位为 N·m/rad，`Ki` 为 N·m/(rad·s)，`Kd` 为 N·m·s/rad。不要把以角度制整定的参数直接混用到弧度制程序中。

## 4. 先运行一次基准实验

按 README 完成环境准备，然后在仓库根目录执行：

```bash
python lab.py
```

网页默认设置为 Yaw=45°、Pitch=20°、外力矩=0.08 N·m，不勾选反向。

| 时间 | 发生的事件 |
| --- | --- |
| 0–1 s | 目标为 0°，初始角度和速度为 0 |
| 1 s | 目标阶跃至输入值 |
| 6 s | 两轴分别加入同样的持续外力矩，保持到仿真结束 |
| 8 s | 若勾选反向，则两轴目标变为输入值的相反数 |
| 15 s | 仿真结束，可拖动时间轴回看 |

每次编译后 C++ 先计算完整的 15 s 数据，浏览器随后播放。因此曲线从一开始就显示整段响应；竖线表示当前动画时间。播放倍速不会改变控制计算。

右上选择 Yaw 或 Pitch 只切换曲线，左侧动画始终显示两轴。保存 CSV 可进一步分析；灰线仅保留当前页面会话中上一次成功运行的实际角度，刷新页面会清除比较记录。

## 5. 实验一：只开 P，观察速度与超调

打开 `src/tuning.cpp`，将 **yaw_gains()** 改为：

```cpp
Gains yaw_gains() {
    return {0.8, 0.0, 0.0, 0.65, 0.025, true};
}
```

数组顺序依次为 `Kp, Ki, Kd, max_output, derivative_tau, anti_windup`。

1. 网页外力矩设为 **0**，Yaw 保持 45°，不勾选反向。
2. 保存代码并点击“编译并运行 C++”。
3. 将 Kp 分别改为 **0.2、0.8、2.0**，每次只改这一项，保存、编译、记录。
4. 对比超调、振荡和首次到达目标附近的速度。

问题：Kp 增大后是否始终更快？当力矩已达到 0.65 N·m，再增加 Kp 能否继续增加初始加速度？

在这个无恒定负载的模型里，仅 P 也可以最终到达目标附近。不要据此认为所有 P 控制器都有或都没有稳态误差。

## 6. 实验二：加入负载，寻找 P 的局限

将 Yaw 参数恢复为 `{0.8, 0, 0, 0.65, 0.025, true}`，网页外力矩设为 **0.08**。

1. 运行后拖到 6 s 之前，观察角度。
2. 再拖到 14–15 s，记录误差与力矩。
3. 注意本实验的正外力矩将云台推向正角度，实际角度可能高于目标。

稳态速度、加速度为 0 时，电机需要抵消外力矩：

```text
Kp · e + load = 0
e = -load / Kp = -0.08 / 0.8 = -0.1 rad ≈ -5.73°
```

P 需要保留一定误差，才能产生维持平衡的力矩。这里误差的符号也告诉你偏差方向。

## 7. 实验三：加入 I，观察补偿与代价

保持网页设置，改为：

```cpp
return {0.8, 0.45, 0.0, 0.65, 0.025, true};
```

1. 保存、编译，观察 6 s 后 I 项如何变化。
2. 比较末秒平均绝对误差与上一轮 P 控制。
3. 同时比较 1–6 s 的超调、振荡。消除长期误差不代表整个过程都更好。
4. 尝试 Ki=0.15，再与 Ki=0.45 对比。不要同时修改 Kp。

问题：当误差已经很小，I 项为什么仍能非零？它“记住”的是什么？

## 8. 实验四：加入 D，减轻超调

改为默认 PID：

```cpp
return {0.8, 0.45, 0.22, 0.65, 0.025, true};
```

1. 保持相同目标和负载，编译运行。
2. 比较 PI 与 PID 的初次超调、振荡，以及受负载后的恢复。
3. 尝试 Kd=0.08、0.22、0.40，记录结果。
4. 在 1 s 目标跳变时检查 D 曲线：本实现不会因目标跳变本身产生冲击，而是在角度运动后产生阻尼作用。

微分滤波时间常数默认 0.025 s。增大它会更平滑，也会增加滞后；本模型没有传感器噪声，不能仅凭本实验断言真实硬件无需滤波。

## 9. 实验五：亲眼看到积分饱和

这轮有意让电机“力气很小”，让输出长时间饱和。

网页设置：Yaw=**120°**、Pitch=20°、外力矩=**0**，**勾选 8 s 时反向目标**。

先关闭抗积分饱和：

```cpp
return {0.8, 0.45, 0.22, 0.08, 0.025, false};
```

1. 编译运行，观察白色输出曲线停在 ±0.08，但 I 项还能继续累积。
2. 暂停并拖到 8 s，目标已反向时，电机输出是否立即反向？
3. 仅将末尾的 `false` 改为 `true`，重新编译。
4. 比较反向后的力矩符号与恢复过程。不要只比较一个超调数字。本组参数在 8 s 时两者都能立即产生负力矩，但关闭抗饱和后仍有明显的后续振荡与大误差；积分饱和并不总表现为反向瞬间的输出符号错误。

本实现使用条件积分：若候选总输出超出上限，且误差还会让饱和更严重，则本周期不接纳新增积分；如果误差方向有助于退出饱和，仍允许积分更新。

输出限幅与抗积分饱和解决不同问题。限幅限制电机实际输出；抗积分饱和处理控制器内部“越积越多”的状态。本例没有使用回算抗饱和，也没有额外设置积分限幅。

完成后恢复默认参数、45°/20° 目标、0.08 N·m 负载并取消反向。

## 10. 如何评价“调好了”

一次只改变一个因素，并保持目标、负载和其他参数一致。使用 `docs/实验记录模板.md` 记录：

- **超调**：初次阶跃的 1–6 s 窗口内，实际角度沿目标方向越过目标的最大幅度 / 目标阶跃幅度。目标为 0 时显示“—”。
- **末秒平均绝对误差**：14–15 s 内 `abs(target - actual)` 的平均值。它是有限窗口统计，不保证系统已达到稳态。
- **调整时间**：可从 CSV 自行计算首次进入且此后一直保持在指定误差带内的时间。必须声明误差带和观察窗口，页面没有自动给出此指标。
- **饱和与恢复**：输出在上限停留多久，反向后是否及时改变力矩方向。

没有唯一最佳参数。更快响应、更小超调、更少力矩和更强抗扰之间常有取舍。

## 11. C++ 执行顺序与模型边界

阅读 `src/main.cpp`，对照每个周期：目标生成 → 读取当前角度 → PID 更新 → 记录数据 → 物理模型积分。

```text
J · acceleration = motor_torque + external_torque - b · velocity
velocity += acceleration · dt
angle += velocity · dt
J = 0.035 kg·m²，b = 0.06 N·m·s/rad
```

这是半隐式欧拉积分的简化双轴模型。两轴参数相同且互不耦合，没有机械限位、角度环绕、重力力矩、摩擦死区、电机电气动态、通信延迟或测量噪声。动画表示模拟姿态；大幅不稳定的参数可能使模型超出真实云台的运动范围。

控制频率 500 Hz，CSV 每 10 步记录一次，即 50 Hz；记录频率不等于控制频率。CSV 中 `yaw/pitch/target` 单位为 °，`*_u/*_p/*_i/*_d/load` 为 N·m，`time` 为 s。`load` 是每个转轴受到的同一外力矩数值。

## 12. 迁移到嵌入式时还需要什么

`PID::update()` 可作为控制模块的起点。迁移时将仿真角度替换为编码器或姿态估计角度，使用定时器或固定周期任务，每个转轴保留独立的 PID 实例和状态。

实际工程还需要确认反馈极性、角度单位、采样周期、输出到电流或 PWM 的映射、机械限位及失能处理。角度跨越 ±π 时要按应用定义最短角度误差；这个实验没有做角度环绕。很多真实云台采用位置环 → 速度环 → 电流环，本实验只实现角度到力矩的单环。

重新使能或切换控制模式时应明确如何调用 `reset()`，避免带入旧积分。这里的仿真参数不能直接作为真实硬件的整定结果。
